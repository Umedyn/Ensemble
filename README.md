# Ensemble

A local, character-driven story sim in the spirit of Pax Historia, but at personal scale: you play one person in a group, and every other member is their own character with wants, needs, secrets and feelings. Runs entirely in the browser against KoboldCpp.

## Running it

1. For a local model, start KoboldCpp with any instruct or roleplay model. 8K context or more is recommended. Set the **chat completions adapter** to match your model's format (for Mistral Nemo-based models such as NemoMix, pick the Mistral/Nemo adapter). If the console says "Chat template heuristics failed… Alpaca will be used", the model is being prompted in the wrong format and quality will suffer. Using a hosted model instead? Skip this step; you only need an API key (see below).
2. Double-click `start.bat` (Windows) or run `./start.sh`. This serves the folder at http://localhost:8000 (using Node if installed, otherwise Python) and opens your browser. With Node you can also run `npm run serve`.
3. On your first visit, a short setup asks how you want to run the model (hosted, KoboldCpp, or both), checks whether KoboldCpp is running, and opens Settings where you finish up. **Settings → Setup guide** brings it back.
4. Pick a world (and, if it has more than one, where you start), press **New game**, and type what you do.

No Python? Open `index.html` directly and use **Open folder** to pick the `scenarios` folder (or a single world folder).

Each backend has its own context size: **Test** reads it from KoboldCpp, or from the provider's model list when it has one (OpenRouter does). Settings also has the memory cap, scene length, temperature and the most turns a chapter runs.

**Settings → Appearance** sets the theme (Dark, Light, **High visibility** for low vision, or the same as your device), text size (90–150%), story font (serif or sans), line spacing, reduce motion and map detail (detailed floor plans, or simple boxes for older phones). Changes show as you pick them and are kept in this browser. With a screen reader, each new beat and note is read out as it appears.

## Models: local, remote or API

**Settings** has two backends, each with presets:

- **KoboldCpp on this computer** (default, `http://localhost:5001`)
- **KoboldCpp on my machine (remote)**: start KoboldCpp with its remote tunnel option and paste the public URL it prints, or use your PC's address on your home Wi-Fi. Lets you play on your phone with your own GPU doing the work.
- **OpenRouter**: one API key, many models. Paste a model name from its list (`vendor/model-name`).
- **Other OpenAI-compatible API**: any provider that speaks the OpenAI chat format and allows calls from a web page.

Under **Which model does what**, each step (characters & events, narration, memory updates, chapter summaries) can use either backend. **Hybrid** sends characters, events and narration to the external model and keeps bookkeeping local. Use **Test** on each backend; errors say what's wrong (bad key, unknown model, out of credits, can't reach).

API keys are stored only in your browser and are never written into save files.

## Playing on a phone, or sharing a prototype

Ensemble is plain HTML and JavaScript, so it can be hosted as-is on any static host (GitHub Pages, itch.io as an HTML game, Netlify). Open the link on a phone; the crew and situation panel slides up from the 👥 button.

To hand it to someone without a GPU: send them the link, have them open **Settings → External model → OpenRouter**, paste their key and a model name, then press **All external**.

Note: a page hosted on `https://` usually can't reach `http://localhost`, so on a hosted copy use the remote KoboldCpp URL (which is `https://`) rather than localhost.

## How a turn works

1. **Intent** (1 model call): judges your action (does it need a skill roll? does it move you?), decides what each character in the room tries to do (including covert actions), and sets **events** for the timeframe: offstage characters pursuing their own goals, arrivals, calls, equipment trouble. Events are *seen* (in your room), *heard* (a sound, call or message) or *hidden* (recorded as private knowledge for whoever was involved). Longer time steps allow more events.
   Events come in three tiers. **Local** events involve the people in and around the scene. **Regional** events happen in the surroundings (terrain, weather, nearby places) and **world** events are broad shifts far away (organizations, money, politics, disasters). The engine decides when a regional or world event is due from the scenario's `eventRates`, with cooldowns, so they stay rare; bigger events carry concrete effects on world status, group stances, pressure clocks and regions (who holds one, its tags and status line), and can add a new pressure. Known regional and world events appear under **News**.
2. **Resolve** (no model call): d20 + skill×2 vs a difficulty (8 / 12 / 16), with penalties for injury and exhaustion. Time advances, needs tick, crisis clocks advance and can fire.
3. **Narrate** (1 call): writes the scene from your point of view. The narrator never sees anyone's secrets, and covert actions are only hinted at.
3b. **Beats:** the scene is written in beats, each starting with a time marker (`[+0m]`, `[+40m]`…): one for a minute or a few minutes, up to four overnight. **A minute** is for dense conversations: each exchange moves the clock one minute, so a long talk doesn't eat the evening. The page shows one beat at a time, with **Step in here** and **Next ▸** under the newest one. Next settles that beat and shows the following one. Stepping in (or simply acting before you reach the last beat) cuts the turn at that point: later beats never happen and are never shown, time only advances to that moment, and your next action starts there. "About an hour" and "A few hours" are approximate: the clock follows where the scene actually ends, and a scene that stops before half the step is asked to continue once.
4. **Update** (1 call, at the start of your next turn, so it only records the part of the scene you let play out): returns facts, state changes and relationship shifts as JSON. The engine validates everything (real IDs, allowed fields, clamped values) and rejects the rest; the Debug panel shows what was accepted or rejected.
5. **Chapter** (occasional call): when the minor facts of the chapter have grown enough to be worth rolling up (about a third of the memory set aside for facts, after at least 4 turns), or at the latest after 12 turns (Settings), they are rolled into a journal entry to free context. In the story, a closed chapter folds into one row that opens to its summary and its turns. Major facts (weight 3) and characters' private knowledge are kept individually.

If a call fails, the turn is rolled back. If only the update step fails, the scene is kept and a basic fact is recorded instead.

**💡 Suggest** (optional, 1 call) asks for three or four ideas for your next action. Clicking one puts it in the action box, where you can edit it; nothing happens until you press **Act**. The model sees only what you know and the scene as far as you've read it (up to your step-in point), and the call goes to the backend routed for characters & events.

## Skipping to the next major event

**⏭ Until something major happens** fast-forwards through downtime (days or weeks) and stops at whichever comes first: a pressure clock running out, a random major event (on average every `majorEventDays`), or the horizon (`majorHorizonDays`, default 30). During downtime people eat and sleep, so hunger and fatigue settle instead of climbing. The scene comes back as a short montage of day-stamped beats followed by the interrupting event as a live scene, with everyone wherever they were when it hit. You can type a plan for the downtime ("keep the arrays clean and avoid Teo") or leave it empty, and you can still step in after any montage beat.

Clocks can have follow-ups (`then`): when one fires, new pressures start. In Ares Deep, the storm arriving starts "Storm clears" and "Battery reserve depleted"; whichever runs out first is what the next big skip stops at, unless something else happens sooner.

## Memory and context

Prompts are ordered for KoboldCpp's prompt cache: a fixed header (rules, setting, places, cast), then chapter summaries and facts the player knows, then everything that changes per call. The header is identical for all calls in a turn and only grows at its end between turns, so most of it is reused. Context is the smallest among the backends in use (the shared header goes to all of them), capped by the memory cap (default 32K) so a huge hosted context doesn't inflate every prompt. It sets a **tier**: compact (up to 10K), standard (up to 24K) or roomy. A compact context gets a shorter outline of the map, fewer nearby regions and only the groups that are around, and its memory is fitted into what's left after the reply, the fixed header and the turn's own message, so a game forty turns in still fits 8K; standard and roomy keep facts at about 20% of context and chapter summaries at about 12%. A call that would still overflow drops its lore, then the start of the last scene, and says so in Debug. `npm run context` prints what every part of every prompt costs at each size.

Every fact records who knows it (`known_by`). The narrator only gets facts the player knows; each character's intent only gets their own private knowledge.

## Making a world

A **world** is everything that's true wherever you start: the setting, rules, skills, groups, event pacing and a pool of characters. A **start** is one way into it: when, where, who you play, who's around you, the local pressures and the opening scene. One world can have several starts; Ares Deep has two (Kit in the commons, Priya in the garage).

Copy a folder in `scenarios/` and edit it:

```
scenarios/my-world/
  world.json
  starts/<id>.json       one file per id listed in world.json "starts" (the first is the default)
  characters/<id>.json   one file per id listed in world.json "characters"
```

Then add the folder to `scenarios/index.json` (only needed when running with the server; **Open folder** finds worlds on its own). Worlds are validated on load, with readable errors for unknown locations, skills, relations, cast members and so on. With Node installed, `npm run check` validates every world and every start, and warns about field names it doesn't know (a typo like `oppening`).

**The smallest world** is a `world.json` with only `title` and `setting`: no starts, characters, skills or regions. The picker then offers **✦ Make my own start**, and everything else below is optional.

**world.json** fields: `format` (`2`, may be left out), `id`, `title`, `date` (optional `{day, hour}`: when a generated start begins, and an authored start without `start`; default day 1, 9:00), `calendar` (optional `{"day1": "1939-09-01"}`: the real date of day 1, so days read as dates, "Thursday 16 April 1942", in the game and the prompts; without it they read "Day 12"), `summary` (one or two lines for the picker), `tags` (genre tags, most important first: `survival`, `slice-of-life`, `romance`, `intrigue`, `war`, `horror`, `mystery`, `comedy`, `cozy`, `grim`, `adventure`, `political`, or your own words; up to 8), `toneNote` (a sentence on the tone you want), `setting`, `rules` (list), `timeLabel` ("Sol", "Day"), `wakeHour`, `skills` (list), `needs` (`{id, label, perHour}`; leave it out, or use `[]`, for a world without needs: no bars, no penalties; an optional `limit` says what happens to a player who skips ahead without seeing to it: `{relief, missing, text, worst, grace, after}`, where `relief` is the words in a skip plan that cover it (like `["sleep", "rest"]`), `missing` names what they went without, `text` is what happens ("collapses from exhaustion"), `worst` is the worst health it can leave them in (`ok`, `hurt`, `badly_hurt`, `dead`), `grace` is the hours a body lasts at the limit, and `after` is where the need drops back to; fatigue, hunger, thirst, stress and fear have built-in limits, and any other need gets a plain one, so each field is optional), `skillPenalties` (optional: `{health: {hurt: -2, badly_hurt: -4}, needs: [{need: "fatigue", at: 0.85, penalty: -2}]}`, today's values shown; a need the world doesn't have never applies), `revealPressure` (optional: which needs count as pressure for cracking secrets, default `["stress", "fear"]`), `world` (key → short description), `factions` (groups such as an organization, gang or government: `{id, name, desc, stance}`; their stance can shift as events ripple out; optional `allies` and `enemies`, lists of group ids), `reputation` (the player's standing with each group at the start, `{"convoy": 20}`, −100 to 100; starts and player slots may change it), `eventRates` (`{regional, world}`: average in-game hours between regional and world events; 0 turns a tier off), `eventSeeds` (`{regional: [...], world: [...]}`: idea lists that steer what those events are about; an idea can be `{"text": "...", "region": "region_id"}` for something that happens in one region), `regions` (see below), `majorEventDays`, `majorHorizonDays` and `majorSeeds` (for the major-event skip), `tiers` (optional: `{demoteAfter: 4, maxLocal: 6}`, see cast tiers below), `extras` and `inventExtras` (minor people, see below), `facts` (public facts true everywhere), `characters` (the pool: ids; optional), `starts` (ids; optional: none means generated starts only). `locations` can go here too when every start shares the same rooms, as in Ares Deep.

**starts/&lt;id&gt;.json** fields: `id`, `title`, `summary` (who you are and what's going on), `start` `{day, hour}`, `player` (a cast id), `region` (where the player starts, when the world has regions), `cast` (who's in this start), `castLabel` (sidebar heading), `locations` (`{id, name, desc, connects, region}`; `region` defaults to the start's), `clocks` (`{id, name, value, max, perHour, fireText, fireWorld}`, with `then` for follow-up clocks started when a clock fires; `fireHarm` (`"all"` or `"outside"`) makes everyone, or everyone outside, one step more hurt when it fires, and `repeat: true` starts it again after it fires, so it keeps hurting until someone deals with it; `"ending": true` makes it end the story when it comes to a head), `facts` (public starting facts), `opening` (first scene), `playerSlot` (see below). A start can also override world fields: a different `world` status, a group's `stance`, extra `rules`, and so on. Lists of rules and facts add to the world's; rooms, clocks and groups with the same `id` change the world's version field by field.

**Making your own character.** Give a start a `playerSlot` and the picker offers "Play as <name>" or "Make my own" (leave out `player` and everyone makes their own): `"playerSlot": {"location": "commons", "summary": "You make your own crew member...", "roles": [{"id": "systems", "label": "Systems engineer", "desc": "Keeps the air and water running.", "skills": {"tech": 3}, "suggestedTraits": ["practical"]}], "peoples": [...], "freeform": false, "skillPoints": 10, "maxSkill": 3, "relationsDefault": 10, "castFeelings": 10}`. The form asks for a name, pronouns, age, a role (and people, if listed; `"freeform": true` lets players write their own), who they are, appearance, traits (with ideas from the role), voice, what they want, an optional secret, skills (point-buy: `skillPoints` to spend, up to `maxSkill` each; a role's `skills` are filled in first), a portrait (from `portraitSet`, the stand-in, or initials only) and starting feelings toward each person (`relationsDefault`, a number or `{id: n}`). `castFeelings` is how they feel about the newcomer, `knows` and `needs` are the made character's private starting facts and needs, and `summary` replaces the start's summary in the picker. The authored player leaves the cast unless `"keepDefault": true`. **💡 Suggest** next to traits, voice and description asks the model for an idea (routed with World building); nothing changes until you pick it. **Save this character** (in the form, or on your card's Details) downloads it as a character file, and **Load character** fills the form from one. Both bundled worlds' default starts have a slot.

**Making your own start.** A world with no starts always offers it; a world with starts opts in with `"generatedStarts": {"roles": [...], "skillPoints": 10, "maxSkill": 3, "castSize": [3, 5]}` in `world.json` (every field optional; those are the defaults besides `roles`) and mark the regions players may start in with `"startable": true` (it takes in everything inside a region; `false` shuts a branch out). In a big world the start picker searches by name, shows a tree or the map, or picks one for you (🎲 Surprise me), and you can say where exactly you start ("a moisture farm outside the city"). The start picker then offers **✦ Make my own start**: pick where, make your character (or describe one in a line) and say what kind of story you'd like, and the story engine builds the rooms, three to five people with their own wants and secrets, how they feel about each other, one or two pressures (each may start a follow-up when it comes to a head), a few ideas for later events around the place, minor people and groups, an opening, and a few notes of local lore (the diner, the street's market) that keep those details the same from turn to turn, one small checked step at a time (routed with World building). A step the model gets wrong is retried with the problem named, and any step can be redone; progress is kept in the browser, so a closed tab picks up where it stopped. With no starts at all, it's the only choice. With `"customSetting": true` the player also describes the world itself ("a fishing village on a Scottish island in the 1950s") and the first step turns that into the story's own setting and genre tags, which the review lets you edit; **Your own story** is a bundled world that does only this, for a fully custom story. Harmon's has it; Ares Deep, a closed five-person station, doesn't. When it's done you get a **review**: the opening, the places (with a map), the people and the pressures, every field editable and checked as you type, with **↻ Reroll** for one room, one person, the pressures, the minor people, the opening or the local lore (the rest stays; a lore note can also be taken out with ✕). Secrets, private facts and story-engine notes are hidden until you tick **Show spoilers**. **Save as start** downloads a zip (the start, a character file per new person, and `world.json` with both added to its lists) to unzip over the world folder, where it loads like any authored start; **Play** starts it now. Neither works while the review lists a problem (a field that doesn't validate, a secret in the opening, a pressure that gives one away).

**New regions.** With `"generatedRegions": {"maxRegions": 6, "keepDays": 7, "routeKind": "road"}` as well, the story can also head somewhere bigger that isn't on the map, another town or a planet: the engine adds it as a region with a short description and a route from where you are, builds a place to arrive at, and lets it fade back to a name if nothing happens there. **New places.** Add `"generatedSites": {"maxSites": 8, "keepDays": 3}` to `world.json` and the story can go somewhere the map doesn't have: "I head to the pharmacy on Main Street" builds the pharmacy (a few rooms, who's there, what there is to find), joins it to where you are, and you arrive at its door. Only your own action takes you there, only where a route goes (a far place is a long trip), and not through a locked door. Events can name new places too, built when you first go. A place is kept if something notable happens there or you go back; otherwise it fades a few days after your visit and is rebuilt (remembering your visit) if you return. Put hand-drawn layouts in `sites/<id>.json` and list them in `"sites"` (the creator's Sites tab draws them on a battlemap or floor plan): a new place that fits one by type or tag uses it, drawn on its picture, and the model only adds the people and details. With `"library": ["modern"]` in `generatedSites`, the shared maps in `library/` for that setting join in (Harmon's gets the roadside diner). Harmon's builds places; Ares Deep doesn't. Debug › "Places made during the story" shows what was built and why. **Map focus.** `"mapFocus": "local"` keeps the tactical floor plan for every place (doors, sight lines, patrols: tense stories); `"region"` makes the city the lived space: the map opens at your district with the places you know as pins, and new places are quick flavour scenes (one to three rooms, built in one call) that grow a floor plan if danger arrives. Left out, a lethal or hostile world is `local` and an everyday one `region`. A library map or start can say `"tactical": true`. Both bundled worlds are `local`.

**Regions.** The map above the rooms: `"regions": [{"id": "junction", "name": "Highway junction", "controller": "convoy", "tags": ["blocked"], "status": "abandoned cars across two lanes", "neighbours": ["highway-strip"], "lore": "Where the highway meets the interstate..."}]`. `controller` is a group id or `null` (no one), `tags` are up to 6 short words, `status` is a line up to 120 characters, `lore` a summary up to 400 (no secrets). Neighbour links work both ways, so listing one side is enough. Every room belongs to a region (the start's unless it says otherwise). Regional and world events can hand a region to another group, add or remove its tags and change its status, as rarely as the event rates allow. The sidebar shows your region; the story engine sees the regions' names, neighbours and lore (on a big map, the ones near the start in full and the rest as names), but who holds what only for your region and what's near it. A start can change a region by `id`. **Regions inside regions:** give a region a `parent` (another region's id) to put it inside that one, up to 6 levels deep where your story needs detail (a country, its zones, a city, its wards) while the rest stays broad; `label` names what it is ("zone", "ward", "planet"), and `regionLabels` in `world.json` gives the word for each level so you don't repeat it. A region with no `controller` of its own shows who holds its parts. The story engine sees the chain you're in (ward › city › country) and what's near, so a deep world costs no more per turn than a flat one. Harmon's is the example: the highway strip, Main Street and the houses are parts of the town of Harmon. **Presence and hidden places:** `"presence": {"convoy": {"junction": 0.4}}` says how strongly a group is in a region besides who holds it (several can be; close ones make it contested), and events can shift it; `"known": false` on a region keeps it, and everything inside it, off the map and out of the story until something reveals it (an event, a fact the player learns, or the player getting there). **Routes and travel:** `"routes": [{"to": "ridge-town", "kind": "road", "time": "45m"}]` on a region says how people get somewhere: a kind (`border`, `road`, `rail`, `sea`, `air`, `checkpoint`, `hyperlane`, `portal`, or your own word), a time, and optionally `requires` (a condition in the timeline's form, such as `{"world": "papers", "is": "yes"}`), `risky` (the player can try anyway, as a roll) and `oneWay`. Neighbours are free borders, so add routes only where travel matters. A closed way stops a move before the story engine is asked; a trip longer than your time step becomes the turn, a journey that pressures and events can interrupt (you then wait "on the way" and can go on). The story engine sees the routes out of your region with their times, and why a closed one is closed. Details: `docs/WORLDS.md` › Routes and travel.

**Lore.** Background knowledge about the world, chosen per turn so a big world still fits a small model: `"lore": [{"id": "rim-work", "title": "Working on the rim", "level": "region", "ref": "crater-rim", "keywords": ["EVA", "dust devil"], "priority": 3, "text": "Every trip outside needs two people..."}]`, or file ids such as `"lore": ["town"]` for `lore/town.json` (one entry or a list). `level` is `world`, `region`, `location`, `character` or `topic`; `ref` names the region, room or character (not for world and topic entries). An entry comes up when the player is in its room or region, when its character is present, or when one of its `keywords` (whole words, any case) is in the player's action or the last scene, best first by `priority` (1–5, default 3) within about a tenth of the context. `topics` (up to 4: `school`, `work`, `business`, `crime`, `military`, `politics`, `religion`, `nightlife`, `family`, `health`, `travel`, `tech`, `science`, `sport`, `arts`, `law`, or the world's own from `"loreTopics": {"scavenging": ["supply run", "looting"]}`) bring an entry in for a player character whose role, traits or tags fit (a character file may add `topics` of its own), or when the scene turns to it, so a student and a manager in the same city get different lore. Where nothing has lore of its own, the world entries come in last. `alwaysOn: true` world entries are always included; keep them short. `text` is up to 800 characters (40–80 words on one topic works best), and `sources` (`[{title, url}]`) are for you, never sent to the model. **Lore is public**: secrets go in a character's `secret`, and the game refuses an entry that gives one away. Starts add or replace entries by `id`. Debug lists which entries each call included and why. Details: `docs/WORLDS.md` › Lore.

**Endings.** How the story can end besides your death: `"endings": [{"id": "got-out", "title": "Out of Harmon", "kind": "win", "when": {"judged": "the player gets out of Harmon for good"}}, {"id": "a-month-on", "kind": "bittersweet", "when": {"after": {"day": 53, "hour": 9}}}]`. A timeline event or a pressure can also just say `"ending": true` (or `{"title", "kind", "epilogue"}`) to end the story when it happens. `when` is a timeline `event`, a time (`after`), a pressure coming to a head (`clock`), the player getting somewhere (`reach`: a room, or anywhere inside a region), or `judged`: something the scene has to show, which the story engine rules on while it records the scene (it has to quote it). `if` adds conditions in the timeline's form, and `kind` (win, loss, bittersweet, neutral) and `epilogue` set the closing's tone. The scene that reaches an ending closes the story, then an end card offers **Keep playing**. Details: `docs/WORLDS.md` › Endings.

**Lore packs.** Add-on lore for a world, made by anyone without changing the world: a folder `packs/<id>/` with `pack.json` (`{"id", "title", "world", "version", "credit", "license", "lore": [...], "timeline": [...], "loreTopics": {...}}`), listed in `packs/index.json`. Pick a world, then **Lore packs** to tick the ones you want; they're added at New game and your saves keep them. A pack only adds entries (a world may let them replace its own with `"lorePacks": {"replace": true}`). The Creator's Lore tab makes, imports, edits and exports them. `packs/harmon-county` is an example for the holdout. Details: `docs/WORLDS.md` › Lore packs.

**Canon timeline.** Dated events: `"timeline": [{"id": "convoy-checkpoint", "when": {"day": 26, "hour": 9}, "scope": "regional", "region": "junction", "text": "The rescue convoy reaches the junction and sets up a checkpoint.", "effects": {...}, "preconditions": [{"controls": {"group": null, "region": "junction"}}], "onBroken": "diverge"}]`. Events before the start are the past: they become facts and a "Before the story" chapter. Future ones happen on their date as news (with their `effects`), outside the usual event pacing, if their `preconditions` still hold: `alive`, `controls`, `clock` with `atLeast`, `world` with `is`, `known` (an event id, or `{"words": [...]}`, optionally `by` someone) and `not`. If one broke, `onBroken` decides: `drop` (the default) or `diverge` (the model writes what happens instead). `visibility` is `heard` (default), `seen` or `hidden` (only `who` learn of it). `"moves": [{"id": "reiko", "to": "tokyo-campus"}]` sends people to a room when the event happens as written (the third-years off to university at graduation), and people whose `joins` names the event come into the story with it. "Until something major happens" stops at the next one. When nothing is planned for the next few days, the model plans a few likely events (an exam, a holiday, a delivery) so the story keeps its pace; `"projectTimeline": false` turns that off and `{"days": 3, "max": 3}` tunes it. Never put future events in lore or descriptions. Details: `docs/WORLDS.md` › Canon timeline.

**Research helper.** `npm run research -- plan <world>` lists what to research from the world itself (the world, its regions, groups and characters) in `research.json`; trim it (`"skip": true`), or point a topic at a wiki `page`, a `url` or pasted `text`. `npm run research -- run <world>` reads each source (Wikipedia by default; `--wiki` takes any MediaWiki wiki, such as a Fandom one) a part at a time and has your model draft short lore entries (each with the topics it proposes from the world's list) and, with `--date YYYY-MM-DD` (the start's real date), dated timeline events. It uses KoboldCpp on this computer, or an API with `--backend external --url … --model …` and the key in `ENSEMBLE_API_KEY` (never saved). The engine refuses copied text, oversized entries, entries about nothing in your world and anything that gives away a secret; secrets and undated later events are printed as suggestions. Everything lands as drafts the game ignores until you accept them in the creator's Lore and Timeline tabs. It runs only while you build a world, never during play. Worlds made from franchise wikis are for your own play and mods.

**cast** entries are a character id, or an object that sets where that person is and how they feel in this start: `{ "id": "bauer", "status": { "location": "hydro" }, "needs": { "stress": 0.7 }, "knows": ["..."] }`. An entry can override `status`, `needs`, `relations`, `knows`, `want`, `secret`, `guard` and `tags`, and can set `tier` (`"local"` or `"secondary"`), `pinned` (`true` keeps that person local) and `agenda` (see below).

**The map.** Next to the story there's a map of the rooms you know, with everyone where you last saw them (people out of sight are faded; the cards say "last seen in…" too). Switch between Text, Split and Map above the story; on a phone, 🗺 swaps the story for the map. Clicking a room or a person fills in the action box. The game plays by it: you move only through linked rooms, a locked door stops everyone but whoever holds its key (picking a lock takes a roll), shut doors block your view, and cameras or watched entrances on your way make sneaking harder. Use something the map doesn't list ("I climb out the back window") and it's added if nothing contradicts it. A world can shape it: rooms take `size` (`small`, `medium`, `large`), `level` (1 for upstairs or a roof), `outside`, `features` ("forklift", "the pickup"), `seen: false` for a room you don't know yet, and `links` (`[{"to": "roof", "kind": "hatch"}]`; kinds `open`, `door`, `locked door`, `vent`, `hatch`, `window`, `stairs`; a locked door can name `"key": ["ferris"]`). Features can carry a state (`{"name": "camera", "state": "on"}`), and `entrances` (`[{"room": "dock", "kind": "roller door", "watched": true}]`) mark ways in from outside. `"site": {"type": "hall"}` or `"corridor"` picks a layout style, and `localMap` (`{image, width, height, rooms: {id: {x, y, w, h}}}`) uses your own floor-plan picture instead.

**The creator.** **Creator** in the top bar opens `creator.html`, where you can open a world (from the server list or a folder) and edit it with live validation; your edits are kept in the browser until you export. The Map tab draws regions on a map image (click corners, drag to adjust, or place a point), sets who holds each region, its tags, status, lore and borders (it suggests regions whose outlines touch), places rooms on the map, and sets each start's region and each group's colour. Regions form a tree: **+ Inside** and **+ Next to it** add regions, and dragging one onto another puts it inside. Each region can have routes (a kind, a time, one way, risky, and what it needs) and **Attach a map…** for a picture of the regions inside it; the **Route kinds** table sets how each way of travelling works for the whole world. The Lore tab edits lore entries by what they are about, with keyword chips, topic tags (and topics of the world's own), priority and sources, and a test box that shows which entries a room and an action would bring in, and their token cost. The Timeline tab lists events before and after the start, and edits each one's date, place, text, who hears of it, its conditions (picked from the world's real people, groups, regions, pressures and events), what happens if one breaks, and its effects; it also turns planned events for quiet stretches on or off. The World tab edits the setting, rules, genre tags (with what each one means for the story), time, skills, needs (or none), pacing, event ideas, world status and public facts. The Groups tab edits each group's name, description, stance and colour. The Starts tab adds, duplicates and removes starts and edits each one: its date and region, who you play (or a slot where players make their own), the cast with where each person starts and what they feel and know there, the rooms and the ways between them (with a preview of the local map), pressures and what follows them, minor people, groups of people, facts and the opening. The Characters tab edits the world's people in the same form players use to make their own character, plus what only an author sets: the secret, what they know, an agenda, whether they start in the foreground, tags, starting needs, feelings toward everyone, and a portrait from your own image files. **Import a card** brings in a SillyTavern/Tavern character card (PNG or JSON, card versions 1–3): one call to your model (routed with World building) turns it into a person who lives in this world, keeping the card's personality and leaving out its own scenario, first message and system prompt; the engine also cuts any line written to the player or taken from the card's scenario, and tells you. You review the sheet before it is added, and the card's image becomes the portrait only if you tick that you have the right to use it. The Portraits tab manages the stand-ins (`portraitSet`) and shows who gets which. The Sites tab turns battlemaps and floor plans into site maps (see `MODDING.md` › Site maps). **New world** starts from a blank world that already loads, or from a template (One country with provinces, One city, Planets and travel) with regions, labels and route kinds set; **Open zip** opens an exported world; **▶ Test play** opens the game in a new tab with the world as it is now, without exporting (it never touches your own saved game). **Export zip** downloads the whole world folder, images included; unzip it into `scenarios/` or open it with **Open folder**.

**Real places.** **New world** in the creator can start on the shared topographic world map (from Natural Earth, public domain): pick an area and the map knows where it is on the globe, so the Map tab shows latitude and longitude, and places (capitals, cities) go where they really are. Regions can have several pieces (islands). `npm run basemap -- fetch` once, then `npm run basemap -- regions <world> --within --places capitals` adds today's countries and capitals to a world (or `--pick "France, Italy"`), with neighbours from their borders and their Wikipedia pages for the research helper; `crop` cuts a sharper picture for a small area. It also builds a tree: `--from states` puts provinces under their country, `crop <world> --region france` gives a country its own map, and cities go in their province as pins or (`--as regions`) as regions. A big map keeps the prompt small: the start's surroundings in full, the rest as names. **The world today** is bundled as the base for modern-day worlds: every country and every city of a million or more, each with its Wikipedia page for the research helper and no lore yet; play it as it is (make your own start anywhere) or copy it. **Occupied France, 1942–1944** is a historical world built the same way: France on its own map with the zones and départements of 1942, the demarcation line as a border with risky crossings, Paris, Lyon and Marseille as region maps (arrondissements from IGN's open data, Licence Ouverte 2.0, credited in each map), a real calendar and a canon timeline to the liberation. **Seiryo High** is a slice-of-life world on Japan's map: the prefectures from Natural Earth, Tokyo's wards and Ibaraki's towns from MLIT's municipal outlines (credited in each map), close-ups of Mito and of Daigo's hot-spring valley, the school, the dorm and the family's house as floor plans of their own (a room's `site` makes a separate place, joined to the others by `trip` links), and a school calendar from the entrance ceremony in April 2026 to graduation in March 2029, with a cast of thirty-four (some join in the second term and the second year). Details: `docs/WORLDS.md` › Base maps and real places.

**The world map.** In a world with regions the map zooms through them: a breadcrumb runs from the world down to the room you're in ("Holdout at Harmon's › Harmon › The highway strip › Sales Floor"), with **📍 Where I am** and **🌍 Whole world** to jump. Each level shows the regions in the colour of the group that holds them (a group's `color`, 1–8, picks the colour), with their tags, and your region and the regions it's inside marked; click a region with regions inside it to zoom in, or any other to see who holds it, its status and its lore. **Ways to other places** under the local map lists the routes out of your region ("🚗 Ridge · 45m"); clicking one fills the action box. Any region can have a `map` of its own (the same format), showing the regions inside it; a level without one zooms the nearest picture above it, and with no picture anywhere the game draws the regions as a node map with their routes. Pictures are always underneath: decoration, never data. Add `"map": {"image": "maps/town.svg", "width": 800, "height": 560, "regions": {"junction": {"polygon": [[300, 150], [620, 150], [640, 290]]}}, "locations": {"floor": [515, 322]}}` to `world.json` to draw it on your own picture (the holdout's `maps/town.svg` is an example); without one, the game lays out the regions from their neighbours.

**Cast tiers.** Big casts stay cheap because only **local** people (with you, or important right now) get the full simulation. **Secondary** people are in the background: no turn-by-turn intent, one short line (role, where they are, what they want) for the story's events, never their secret, and their needs settle as if they're keeping to their routine. They're listed under **Elsewhere** in the sidebar. By default the people in your starting room are local and the rest secondary. Someone becomes local when they enter your scene, when your action names them, or when they're in an event you see or hear. They drop back to secondary after `demoteAfter` turns (default 4) without being seen, and if more than `maxLocal` (default 6) local people are away from you, the ones you haven't seen for longest go first. `pinned` people never drop; you can pin or unpin someone yourself from their card (**📌 Pin** under Details, up to `maxLocal` people). Every change shows in Debug.

**Agendas.** A character file (or a cast entry, per start) can give someone a goal they work on while you're elsewhere: `"agenda": {"goal": "prove the deep-ice cultures are alive", "hours": 14, "steps": ["runs a second culture in the unlogged incubator", "checks the results against the controls", {"text": "comes to find Kit, wanting a second opinion", "contact": true}]}`. Steps are short actions without the name, `hours` is how long each takes (1–240, default 12), and `visibility` is `"hidden"` (default: the player never sees the step happen) or `"heard"`. A `contact` step brings them to you, and a long skip can stop there. People in the background make progress; people with you act turn by turn instead. Use `"agenda": null` (or `{"goal": "keep routine"}`) for no agenda; leave the field out and the model proposes one when they first end up in the background. Agendas never show on cards; Debug lists them.

**Relationship web.** **Web** in the people panel shows who feels what about whom: your feelings, how each person treats you, and, between other people, only what you have seen or been told (dashed lines, with the fact that showed it). Words only; exact numbers are in Debug. A toggle adds the people in the background.

**Extras.** Minor people who don't need a full sheet: `"extras": [{"id": "albee", "name": "Mrs. Albee", "pronouns": "she/her", "role": "elderly neighbour", "location": "dock", "note": "keeps a shotgun she says is not loaded"}]`, in `world.json` or a start. `"location": null` means nowhere in particular. Crowds, patrols and hordes are standees (below). Extras have no turn of their own, needs, feelings or card: they show in the scene bar when they're with you, can be part of events and facts, and can move. The `note` is for the story engine and never shown. Name someone twice (on different turns), or have them in an important fact, and one **World building** call (routable in Settings) writes them a full character sheet; they join the cast from then on, keeping everything known about them. With `"inventExtras": true` the model may add new minor people (or a group, as a standee) as scenes need them (one a turn); leave it off for closed settings like a five-person Mars station.

**Standees.** Unnamed groups on the map, such as guards, a gang or a few of the dead: `"standees": [{"id": "stragglers", "label": "stragglers", "count": 5, "location": "lot", "state": "calm", "note": "they bunch up at the dock door when they hear noise"}]`. `state` is `calm`, `alert`, `hostile` or `down`; `faction` (a group id) says who they belong to; `post` (a room they hold) or `patrol` (a loop of linked rooms, one room an hour) make guards. A group acts as one, moves only to a linked room, gets harder to fight or sneak past the more of them there are and the warier they are, and notices you when a sneak fails. Name one in your action ("I grab the nearest straggler") and they become a minor person. A group that is wiped out or flees leaves the map. Groups exist only in rooms; a horde far away is a pressure or a faction. The old `"group": true` extras still load, as standees when they have a room.

**Character files** hold who the person is: `id`, `name`, `pronouns`, `role`, `age`, `traits`, `want`, `secret`, `guard` (`low`, `medium` or `high`: how hard the secret is to crack), `voice`, `skills` (0–4), `relations` (id → −100..100, how they feel about that person), and optionally `portrait` (an image in the world folder, like `"portraits/okafor.png"`; png, jpg, webp, gif or svg), `description` (who they are, up to 600 characters) and `appearance` (up to 400; keep the first sentence a good one-line look, since the narrator sees that sentence for the people in each scene), and `people` (a people or origin, up to 60 characters, shown with the role). `"portrait": false` means initials only, even when the world has a `portraitSet`. A character can belong to groups: `groups` is a list of group ids, or `{"id": "resistance", "role": "favored"}` with a role (`member`, `favored` or `leader`); every group regards the player somewhere from −100 to 100, and the player's own role decides whether they can ask (favored) or order (leader) a group to act. A character can go without some of the world's needs: `needsOff` is a list of need ids (`["hunger", "fatigue"]` for a droid) or `true` for none at all; those needs never grow, give out, show on the card or reach the prompts, and a start's cast entry or a role in a `playerSlot` can set it too. Someone who comes into the story later (a transfer student, next year's first-years, a scout with the convoy) has `joins`: the id of a timeline event after the start; until it happens they are in no prompt and nobody's feelings, and then they arrive where their `status.location` puts them (a start's cast entry can set `"joins": null` to have them there from the beginning). They may also hold `needs` (0–1), `status` `{health, location}`, `knows` (private starting facts) and `tags` (short visible states such as `"bandaged left forearm"`, 32 characters each; they last until the story removes them) as defaults for every start. `status.conditions` from older files is read as tags.

During play, each card shows a **mood** line (how that person comes across right now) and **tags**: ones the story adds (each lasts a few turns, at most 4) and ones from the numbers, such as "on edge" at stress 0.8 or "hurt". A world can change those thresholds with `tagThresholds`: `{"stress": {"at": 0.7, "tag": "frayed"}}`. Needs bars are under **Details** on each card, with the description, appearance and **what you know** about that person (facts you have seen or been told). Details also has **your feelings** toward that person, with − and + (5 a step) and an optional "why": use it when the story misread your tone (sarcasm taken as hostility). Only your own feelings change, the next turn uses the new value, and Undo also undoes corrections made since your last action. A card can be minimized to one row, or all of them with **Collapse all**; the game remembers this per world. People without a `portrait` get a stand-in from the world's `portraitSet` (a list of image paths, picked by id so it never changes) or, without one, their initials. Saves keep only the image paths.

The full spec, including the merge rules, is [docs/WORLDS.md](docs/WORLDS.md). The game lists every start under the world picker; a start with mistakes in it is marked "(has errors)" and shows why.

**Older scenario folders** (one `scenario.json` + `characters/`, no `world.json`) still load, as a world with a single start. `scenario.json` has the world and start fields together, with `characters` as the cast.

Health is one of `ok`, `hurt`, `badly_hurt`, `dead`. Death is permanent; if the player dies, the story ends.

## Saves

Progress autosaves to the browser after every turn. **Save** downloads a JSON file that includes the scenario, so saves work even if the scenario folder changes later.

## Files

- `js/engine.js`: state, resolution, applying validated updates, the turn loop
- `js/memory.js`: facts, `known_by` filtering, chapter rollups, budgets
- `js/genres.js`: genre tags: narrator guidance and default event pacing
- `js/prompts.js`: the four prompt builders
- `js/llm.js`: KoboldCpp client (OpenAI-compatible endpoint), tolerant JSON parsing with one retry
- `js/scenario.js`: loading and validating scenario folders
- `js/charmaker.js`: the character creator (player slots, point-buy, building the character, Suggest)
- `js/startgen.js`: generated starts (the step pipeline, each step's checks, the finished start)
- `js/sites.js`: generated sites (deciding, library maps, building, trip links, keeping and fading)
- `js/ui.js`: the page
